# 自作CPU 命令セット仕様書（草案 v0.9）

2026-10-25 時点（v0.9：BSRAM の残り 4 ブロックを命令キャッシュに。v0.8：ROM を 16KB に戻し、内蔵 RAM を 48KB に。v0.7：ROM を 32KB に。v0.6：CAUSE の割り込みの印を bit31 に固定）

---

## 1. 基本方針

- **32bit / 64bit の上位互換**。モード切替はなし。64bit CPU は 32bit 用の命令をそのまま実行できる。
- **リトルエンディアン**。
- **フラグなし**。比較結果は 1bit レジスタに書き込む。
- 演算の幅（32/64bit）、符号付き／符号なしは**すべてオペコードで区別**する。
- 最初の実装ターゲット：Tang Nano 20K（32bit 版から作る）。

---

## 2. 命令形式

### 2.1 共通ヘッダ（全命令の先頭 32bit）

| bit | フィールド | 幅 | 内容 |
|---|---|---|---|
| 1:0 | width | 2 | 幅（＝命令長を決める） |
| 5:2 | group | 4 | 命令グループ |
| 13:6 | op | 8 | グループ内の命令番号 |
| 19:14 | rd | 6 | 書き込み先レジスタ |
| 25:20 | rs1 | 6 | ソースレジスタ1 |
| 31:26 | rs2 | 6 | ソースレジスタ2 |

- オペコードは width＋group＋op の **14bit**。
- width が最下位にあるので、命令の**先頭1バイトを読めば命令長が確定**する。
- ヘッダの直後に即値が続く。

### 2.2 幅フィールドと命令長

| width | 意味 | 即値 | 命令長 |
|---|---|---|---|
| `00` | システム（幅に依存しない命令） | なし | 32bit（4バイト） |
| `01` | 32bit 演算 | 32bit | 64bit（8バイト） |
| `10` | 64bit 演算 | 64bit | 96bit（12バイト） |
| `11` | 予備 | — | 不正命令 |

- 32bit CPU が width `10`（64bit 命令）を読んだ場合も不正命令。

- 即値を使わない命令でも、即値欄は width に従って存在する（0 埋め）。
- 使わないレジスタ欄も 0 埋め。
- 命令は 4 バイト境界に整列する。
- **オペコード全 0（命令全体が 0）は `HLT`**。空のメモリに飛んだらその場で止まる。

### 2.3 グループ

| group | 内容 |
|---|---|
| `0x0` | システム（NOP, HLT, ERET, SYSCALL など） |
| `0x1` | 算術（ADD, SUB, MUL …） |
| `0x2` | 論理（AND, OR, XOR, シフト） |
| `0x3` | 比較（結果を 1bit レジスタへ） |
| `0x4` | ロード／ストア |
| `0x5` | 分岐・ジャンプ・呼び出し |
| `0x6` | 幅変換 |
| `0x7`〜`0xF` | 予備 |

## 3. レジスタ

### 3.1 レジスタ一覧（番号 6bit、64 個分）

| 番号 | 2進 | 幅 | 用途 |
|---|---|---|---|
| r0 | `000000` | — | 常に 0（書き込みは無視） |
| r1〜r7 | `000xxx` | 1bit | 比較結果 |
| r8〜r15 | `001xxx` | — | 予備 |
| r16〜r31 | `01xxxx` | 32bit | 汎用 |
| r32〜r47 | `10xxxx` | 64bit | 汎用 |
| r48 | `110000` | ネイティブ | PC（読み出し専用） |
| r49 | `110001` | ネイティブ | SP（スタックポインタ） |
| r50 | `110010` | ネイティブ | LR（リンクレジスタ） |
| r51 | `110011` | ネイティブ | EPC（例外発生時の PC） |
| r52 | `110100` | ネイティブ | CAUSE（例外・割り込みの理由） |
| r53 | `110101` | ネイティブ | EVEC（例外ハンドラのアドレス） |
| r54 | `110110` | ネイティブ | STATUS（特権・割り込み状態） |
| r55〜r63 | | — | 予備 |

「ネイティブ」は CPU の bit 数（32bit 版なら 32bit、64bit 版なら 64bit）。

### 3.2 幅の判定

レジスタ番号の上位 2bit が、そのまま命令の width フィールドと対応する。

- 上位 `01` → 32bit（width `01` と一致）
- 上位 `10` → 64bit（width `10` と一致）
- 上位 `11` → 特殊レジスタ（ネイティブ幅）
- 上位 `00` → 3bit 目が 0 なら 1bit レジスタ（全 0 は r0）

### 3.3 規則

- 命令の幅とレジスタの幅が一致しない場合は **HLT**（後で不正命令例外に付け替える）。
- 例外：r0 はどの幅の命令でも使える。
- **特殊レジスタ（r48〜）はどの幅の命令からでも使える**。幅が CPU より狭い命令から読むと下位だけを読み、書くと上位をゼロ拡張する。これにより 32bit のコードが 64bit CPU でも SP・LR を扱える。
- **アドレスに使うレジスタ**（ロード／ストアの rs1、M 形式の rs2、JMPR / CALLR の rs1）は幅の一致チェックの対象外。32bit レジスタの値はゼロ拡張してアドレスにする。
- **アドレス計算の幅は命令の width で決まる**。width `01` の命令は「レジスタ＋即値」を 32bit で計算し（桁あふれは捨てる）、結果をゼロ拡張してアドレスにする。width `10` の命令は 64bit で計算する。これで 32bit 命令は 32bit CPU と 64bit CPU で同じ番地にアクセスする。
  - 例：64bit CPU で `LOAD32_32 r16, SP, -8`（SP ＝ `0x0180_0000`）→ 32bit で `0x0180_0000 + 0xFFFF_FFF8` ＝ `0x017F_FFF8`。
- 比較（`CMP*`）の書き込み先、`SEL` と `BR` の条件、`BTOI` の読み出し元は 1bit レジスタ（r1〜r7）。
- 幅変換命令（グループ 6）は、命令ごとに決まった幅の組み合わせだけを許す。
- PC（r48）への書き込みは不可。PC を変えるのは分岐・ジャンプ・呼び出し・例外だけ。PC を書き込み先にした命令は **HLT**。
- 予備レジスタ（r8〜r15、r55〜r63）を読み書きした命令も **HLT**。
- いずれも、幅の不一致と同じく後で不正命令例外に付け替える。
- r51〜r54 への書き込みはカーネルモードのみ。
- PC と SP の長さは CPU の bit 数に等しい。
- **PC（r48）を読むと、その命令自身のアドレス**が得られる（命令長が可変なので、次の命令ではなく自分自身を基準にする）。

## 4. メモリ

### 4.1 メモリマップ

| 開始アドレス | 内容 |
|---|---|
| `0x0000_0000` | ROM（16KB）。リセット時はここから実行 |
| `0x0001_0000` | 入出力（UART、タイマーなど） |
| `0x0001_8000` | テキスト VRAM |
| `0x0002_0000` | 内蔵 RAM（BSRAM、48KB、〜`0x0002_BFFF`） |
| `0x0100_0000` | メインメモリ（SDRAM 8MB、〜`0x017F_FFFF`） |

- すべて 4GB 以内に置くので、64bit 版でも同じ番地で動く。
- 区切りは切りのいい番地にして、アドレス上位 bit でアクセス先を判定できるようにする。

#### BSRAM の割り振り（Tang Nano 20K：2KB × 46 ブロック ＝ 約 92KB）

| 用途 | 容量 | ブロック数 |
|---|---|---|
| ROM | 16KB | 8 |
| テキスト VRAM | 16KB（実使用 約 14KB） | 8 |
| フォント ROM | 4KB | 2 |
| 内蔵 RAM | 48KB | 24 |
| 命令キャッシュ（SDRAM の命令） | 8KB | 4 |
| 合計 | 92KB | 46 |

46 ブロックを使い切る。命令キャッシュはプログラムからは見えない（SDRAM に書けば、そのラインは自動で無効になる）。

### 4.2 リセット

- リセットベクタは `0x0000_0000`。

### 4.3 整列

- N バイトのアクセスは N の倍数の番地でなければならない。
- 整列していないアクセスは**例外（整列違反）**。

### 4.4 スタック

- `0x0180_0000`（SDRAM の末尾）から**下向き**に伸びる。
- SDRAM を実装する前（BSRAM だけで動かす段階）は、内蔵 RAM の末尾 `0x0002_C000` を SP の初期値にする。
- SP の整列はソフト側の約束（8 章）。

## 5. 命令

全命令のオペコードは **`opcodes.csv`** にまとめてある（1 命令 1 行）。アセンブラ・シミュレータ・Verilog のデコーダはこの表から作る。ここでは割り当ての規則と各命令の意味を説明する。

### 5.1 オペコードの割り当て規則

- 14bit オペコード ＝ width（2bit）＋ group（4bit）＋ op（8bit）。
- `ADDR32` と `ADDR64` のように、幅だけが違う命令は group と op が共通で、width だけが異なる。
- 表記：命令名の末尾の `32` / `64` が width（`01` / `10`）を表す。

#### 算術・論理・比較の形式（op の下位 2bit）

| op[1:0] | 形式 | 命令名 | 動作の例 |
|---|---|---|---|
| `00` | R：レジスタ同士 | `ADDR32 rd, rs1, rs2` | rd ← rs1 ＋ rs2 |
| `01` | I：即値 | `ADDI32 rd, rs1, imm` | rd ← rs1 ＋ imm |
| `10` | M：メモリ（読むだけ） | `ADD32 rd, rs1, rs2, imm` | rd ← rs1 ＋ [rs2 ＋ imm] |
| `11` | 予備 | | |

op の上位 6bit が演算の種類。たとえば ADD は演算番号 0 なので `ADDR`＝0x00、`ADDI`＝0x01、`ADD`＝0x02。

- **M 形式がメモリから読む大きさは命令の width と同じ**（32bit 命令なら 4 バイト、64bit 命令なら 8 バイト）。整列違反もこの大きさで判定する。

### 5.2 グループ 0：システム（width `00`、4 バイト命令）

| op | 命令 | 動作 |
|---|---|---|
| 0x00 | `HLT` | 停止（命令全体が 0） |
| 0x01 | `NOP` | 何もしない |
| 0x02 | `ERET` | EPC へ戻り、STATUS を例外前の状態に戻す |
| 0x03 | `SYSCALL` | SYSCALL 例外を起こす（ユーザーから OS を呼ぶ） |
| 0x04 | `WFI` | 割り込みが来るまで待つ |

### 5.3 グループ 1：算術（R / I / M の 3 形式）

| 演算番号 | 名前 | 動作 |
|---|---|---|
| 0 | ADD | 加算 |
| 1 | SUB | 減算 |
| 2 | MUL | 乗算の下位 |
| 3 | MULH | 乗算の上位（符号付き） |
| 4 | MULHU | 乗算の上位（符号なし） |
| 5 | DIV | 除算（符号付き） |
| 6 | DIVU | 除算（符号なし） |
| 7 | REM | 剰余（符号付き） |
| 8 | REMU | 剰余（符号なし） |

- `SUBI` は作らない。即値が幅まるごと入るので、`ADDI` に負の即値を入れれば同じ（op 0x05 は予備）。
- 0 で割ったらゼロ除算例外。
- 符号付きの「最小値 ÷ −1」（例：32bit の `0x8000_0000 ÷ -1`）は例外にせず、商は最小値そのもの、余りは 0 とする（RISC-V と同じ）。
- DIV / REM 系は回路を小さくするため、1bit ずつ何十クロックかけて計算する方式を想定。

### 5.4 グループ 2：論理・ビット操作

| 演算番号 | 名前 | 形式 | 動作 |
|---|---|---|---|
| 0 | AND | R / I / M | 論理積 |
| 1 | OR | R / I / M | 論理和 |
| 2 | XOR | R / I / M | 排他的論理和 |
| 3 | SHL | R / I / M | 左シフト |
| 4 | SHR | R / I / M | 右シフト（論理、上を 0 で埋める） |
| 5 | SAR | R / I / M | 右シフト（算術、符号で埋める） |
| 6 | CLZ | `CLZ32 rd, rs1` | 先頭の 0 の個数 |
| 7 | POPCNT | `POPCNT32 rd, rs1` | 1 の個数 |

- シフト量は幅−1 でマスクする（32bit 命令は下位 5bit、64bit 命令は下位 6bit だけを使う）。x86 や RISC-V と同じ。

### 5.5 グループ 3：比較・選択

比較は R / I / M の 3 形式。書き込み先は 1bit レジスタ p（r1〜r7）。

| 演算番号 | 名前 | 動作 |
|---|---|---|
| 0 | CMPEQ | p ← (rs1 == 相手) |
| 1 | CMPNE | p ← (rs1 != 相手) |
| 2 | CMPLT | p ← (rs1 < 相手)（符号付き） |
| 3 | CMPLTU | p ← (rs1 < 相手)（符号なし） |
| 4 | CMPGE | p ← (rs1 >= 相手)（符号付き） |
| 5 | CMPGEU | p ← (rs1 >= 相手)（符号なし） |
| 6 | SEL | `SEL32 rd, rs1, rs2, p`：rd ← p ? rs1 : rs2 |

- SEL の p の番号は即値欄の下位 6bit に入れる。
- SEL は短い if 文を分岐なしで書くための命令。回路はマルチプレクサ 1 個。

### 5.6 グループ 4：ロード／ストア

アドレスは rs1 ＋ imm。命令名の `_32` / `_64` は相手のレジスタ（width）。

| op | 命令 | 動作 |
|---|---|---|
| 0x00 / 0x01 | `LOAD8U` / `LOAD8S` | 8bit 読み、ゼロ拡張／符号拡張 |
| 0x02 / 0x03 | `LOAD16U` / `LOAD16S` | 16bit 読み、ゼロ拡張／符号拡張 |
| 0x04 | `LOAD32`（width `01`）／`LOAD32U`（width `10`） | 32bit 読み。64bit レジスタへはゼロ拡張 |
| 0x05 | `LOAD32S`（width `10` のみ） | 32bit 読み、64bit レジスタへ符号拡張 |
| 0x06 | `LOAD64` | 64bit 読み（64bit レジスタのみ） |
| 0x10〜0x12 | `STORE8` / `STORE16` / `STORE32` | rs2 の下位をその幅で書き込む |
| 0x13 | `STORE64` | 64bit 書き込み（64bit レジスタのみ） |
| 0x20 | `SWAP` | 不可分に rd ← [rs1＋imm]、[rs1＋imm] ← rs2 |

- 32bit レジスタへの 64bit ロード、32bit レジスタからの 64bit ストアは HLT。
- width `01` の op `0x05`、`0x06`、`0x13` は不正命令（32bit レジスタには拡張の区別も 64bit 転送もないため）。
- アドレス側の rs1 はどの幅でもよい。アドレス計算の幅は 3.3 参照。
- SWAP はマルチコアや排他制御のためのアトミック命令。シングルコアのうちは割り込み禁止で代用もできる。

### 5.7 グループ 5：分岐・呼び出し

| op | 命令 | 動作 |
|---|---|---|
| 0x00 | `JMP imm` | imm（絶対アドレス）へ |
| 0x01 | `BR p, imm` | p が 1 なら imm へ（p は rs1 欄） |
| 0x02 | `CALL imm` | LR ← 次の命令のアドレス、imm へ |
| 0x03 | `RET` | LR のアドレスへ |
| 0x04 | `JMPR rs1` | rs1 の番地へ |
| 0x05 | `CALLR rs1` | LR ← 次の命令のアドレス、rs1 の番地へ |

- 飛び先は絶対アドレス。即値が CPU 幅まるごと入るので符号の問題はない。
- JMPR / CALLR は関数ポインタや、計算した番地へ飛ぶために使う。
- 関数の中でさらに呼び出す場合、LR をスタックに退避するのはソフト側の責任。

### 5.8 グループ 6：幅変換

| op | 命令 | 動作 |
|---|---|---|
| 0x00 | `EXT32TO64U` | 64bit rd ← 32bit rs1（ゼロ拡張） |
| 0x01 | `EXT32TO64S` | 64bit rd ← 32bit rs1（符号拡張） |
| 0x02 | `TRUNC64TO32` | 32bit rd ← 64bit rs1 の下位 |
| 0x03 | `BTOI` | rd ← p（0 か 1） |

### 5.9 専用命令を作らないもの

| やりたいこと | 書き方 |
|---|---|
| レジスタのコピー | `ADDR32 rd, rs, r0` |
| 定数のロード | `ADDI32 rd, r0, imm`（即値が幅まるごと入るので 1 命令） |
| ビット反転（NOT） | `XORI32 rd, rs, -1` |
| 整数 → 1bit | `CMPNER32 p, rs, r0` |

## 6. 例外・割り込み

### 6.1 発生時の動作

1. EPC ← 戻り先の候補
   - 例外（不正命令、整列違反、SYSCALL など）：**例外を起こした命令自身のアドレス**
   - 外部割り込み：**次に実行するはずだった命令のアドレス**
2. CAUSE ← 理由
3. STATUS の現在の特権・割り込み許可を退避し、カーネルモード・割り込み禁止にする
4. EVEC のアドレスへ飛ぶ

ハンドラは `ERET` で戻る。

- **SYSCALL のハンドラは、戻る前に EPC に 4 を足す**（SYSCALL は 4 バイト命令）。足さないと SYSCALL をもう一度実行して無限ループになる。
- 他の例外で処理を続けたい場合も、飛ばしたい命令の長さ（4 / 8 / 12 バイト）だけ EPC を進める。
- **EVEC のリセット値は `0x0000_0000`**。ROM が EVEC を設定する前に例外が起きたら、リセットと同じ場所から再起動する。ROM の最初の仕事は EVEC の設定。

### 6.2 STATUS（r54）

| bit | 内容 |
|---|---|
| 0 | 特権（0 ＝ カーネル、1 ＝ ユーザー） |
| 1 | 割り込み許可 |
| 2 | 例外直前の特権 |
| 3 | 例外直前の割り込み許可 |
| 8〜15 | 外部割り込み 8 本の個別マスク |

### 6.3 CAUSE（r52）

- bit31 が 1：外部割り込み。下位が割り込み番号（0〜7）。
- bit31 が 0：例外。
- CPU の bit 数によらず bit31 に置く（64bit CPU でも bit63 ではない）。32bit 命令から読めるのは下位 32bit だけなので、こうしないと 32bit 用の例外ハンドラが 64bit CPU で割り込みと例外を見分けられない。

| コード | 例外 |
|---|---|
| 0 | 不正命令 |
| 1 | 整列違反 |
| 2 | 特権違反 |
| 3 | SYSCALL |
| 4 | ゼロ除算 |
| `0xFFFF` | 電源投入リセット（リセット直後の値） |

- **CAUSE のリセット値は `0x0000_FFFF`**。ROM は EVEC 経由で入ってきたとき CAUSE を見て、リセットか例外かを区別できる。

### 6.4 特権

- カーネル／ユーザーの 2 段階。
- ユーザーモードでは、システム命令（width `00`、ただし NOP と SYSCALL を除く）と r51〜r54 への書き込みを禁止 → 特権違反。

## 7. 表示

### 7.1 テキストモード

- 720p、8×16 ドットの文字で 160 × 45 文字。
- 1 文字 2 バイト：文字コード 8bit ＋ 色 8bit（文字色 4bit・背景色 4bit）。
- 合計約 14KB。BSRAM をデュアルポートで使い、CPU が書き込み、表示回路が読み出す。

### 7.2 フォント

- 表示回路の中に専用のフォント ROM（8×16 ドット × 256 文字 ＝ 4KB）。
- CPU のアドレス空間には出さない。
- 将来フォント RAM にして入出力領域に見せる案あり。

### 7.3 グラフィックス（将来）

- 320×200・256 色（パレット）。フレームバッファは SDRAM に置く（64KB）。3 倍に拡大して 720p の真ん中に表示する（960×600）。
- 表示回路は 1 行ずつバーストで読む（1 秒に約 4MB。SDRAM は最大 54MB）。CPU との取り合いを調停する回路が必要。
- 720p・16bit 色は帯域が足りない（1 秒に約 110MB 要る）のでやらない。

## 8. 呼び出し規約（ソフトウェアの約束事）

| 用途 | 32bit | 64bit |
|---|---|---|
| 引数 | r16〜r21 | r32〜r37 |
| 戻り値 | r16 | r32 |
| 呼んだ側が保存 | r16〜r23 | r32〜r39 |
| 呼ばれた側が保存 | r24〜r31 | r40〜r47 |

- **SP は常に 8 の倍数に保つ**（ソフト側の約束。ハードウェアは確認しない。8 バイト未満のアクセスは各アクセスの整列だけが確認される）。
- 1bit レジスタは呼んだ側が保存。
- LR は、さらに関数を呼ぶ場合に呼ばれた側が保存。
